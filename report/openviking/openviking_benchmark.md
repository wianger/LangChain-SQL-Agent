# Openviking Benchmark

**OpenViking** 是一个基于**层次化语义索引**的 RAG 引擎，其核心思想是在文档入库时通过大语言模型自底向上地生成多层级语义摘要，并在检索时沿层次结构递归搜索，从而在语义理解深度与检索效率之间取得平衡。本节详细描述 OpenVikin在评测框架中的文档摄入与检索流程。

## 文档入库阶段

### 文档提交

评测框架通过 **SyncOpenViking** 客户端将预处理后的文档以非阻塞方式提交至 OpenViking 引擎（add_resource(doc_path, wait=False)）。多个文档通过线程池并发提交，提交完成后调用 wait_processed()阻塞等待服务端完成全部语义处理。当语义队列（Semantic Queue）和嵌入队列（Embedding Queue）中的待处理与处理中任务数均为零时，判定处理完成。

### 语义处理

**语义处理**是OpenViking入库流程的核心环节，由 **SemanticDagExecutor** 以 DAG（有向无环图）方式自底向上执行。系统为文档构建三层语义索引结构（L0/L1/L2），各层级的含义如下：

- **L2（原始内容层）**：对于叶子节点（文件），L2存储文件的原始全文内容；对于非叶子节点（目录），L2 对应其所有子节点的集合。
- **L1（概览层）**：存储由大语言模型基于子节点信息生成的目录概览（overview），提供对目录内容的结构化总结。
- **L0（摘要层）**：存储从 L1概览中提取的精炼摘要（abstract），用于上层目录的概览生成以及检索时的快速语义匹配。

具体的构建流程如下：

- **目录扫描与 DAG 构建**：系统递归遍历文档目录结构，为每个目录创建一个 DirNode节点，记录其子目录列表、文件列表及待完成任务计数（pending），形成树状 DAG 结构。
- **文件L0/L1生成**：对每个叶子文件，系统根据文件类型选择对应的 prompt 模板，调用大语言模型生成文件摘要。 摘要生成任务通过信号量控制并发度（默认最大并发数max_concurrent_llm=100）。对于**文本类文件**（.txt、.md、.csv 等），**向量化时使用文件原始全文（L2内容）**；对于**非文本类文件**（图片、音视频等），则使用 **LLM生成的摘要进行向量化**。文件向量化完成后立即提交至嵌入队列，无需等待目录概览生成。 
- **目录概览生成（L1）**：当某个目录下的**所有子文件和子目录均处理完成**（pending=0）时，触发该目录的概览生成任务。系统将所有子文件摘要和子目录摘要作为上下文，通过semantic.overview_generation prompt模板调用大语言模型生成目录概览。
- **目录摘要提取（L0）**：从 L1 概览中提取信息作为目录摘要，供上层目录在**生成其概览**时引用，同时也作为检索时的**快速匹配文本**。
- **目录向量化**：每个目录生成两个向量化条目——L0（.abstract.md，摘要文本）和L1（.overview.md，概览文本），分别提交至嵌入队列进行向量化并写入向量存储。

整个过程**自底向上**逐层推进：先完成所有叶子文件的摘要与向量化，再逐层向上生成父目录的概览与摘要直至根目录处理完成。

### Tokens统计

入库完成后，系统从语义队列中获取 token 消耗统计。

- 输入 token 包括文件摘要生成的 prompt的token和目录概览生成的prompt的token；

- 输出token包括摘要生成的输出 token和概览生成的输出token。

Token 计数采用 tiktoken 库的 cl100k_base 编码器估算。

## 数据检索阶段

OpenViking 采用 **HierarchicalRetriever** 实现层次化递归检索，核心思想是沿文档的语义层次结构从粗到细逐层搜索，通过分数传播机制在父节点与子节点之间传递相关性信号。具体流程如下：

### 查询向量化

系统首先通过嵌入模型（Embedder）将查询文本转换为**稠密向量**（densevector），可选地同时生成**稀疏向量**（sparsevector）用于混合检索。本框架使用的是**稠密向量**。查询向量仅生成一次，在后续所有检索步骤中复用。

### 确定检索起点

系统通过两种方式混合确定检索的起始目录：根据target_uri参数指定的目标目录，是在目标目录中，通过全局向量搜索（search_global_roots_in_tenant）找到语义上最相关的top-K个目录。两组起始点合并后作为递归搜索的入口。

### 递归搜索与分数传播

系统使用**优先队列**（最小堆，按负分数排序）管理待搜索的目录。对于队列中的每个目录，调用search_children_in_tenant()检索其子节点，并通过分数传播公式计算子节点的最终得分：

$$
s_{child}=\alpha \times s_{query} + (1 - \alpha) \times s_{parent}
$$
其中$s_{query}$为子节点与查询的向量相似度，$s_{parent}$为父目录的传播分数，$\alpha=0.5$为传播系数。

**叶子节点**（level=2，即文件级别）直接加入候选结果集；**非叶子节点**（目录级别）重新入队以继续向下搜索。为避免无效搜索，系统设有收敛检测机制：当连续3轮搜索后 top-K 结果集不再发生变化时，**提前终止搜索**。

### 结果排序与热度加权

搜索完成后，系统对候选结果进行最终排序。排序分数融合了语义相似度与热度分数（hotness score），热度分数基于资源的访问频次和最近更新时间计算：

$$
s_{final}=(1-\beta) \times s_{semantic} + \beta \times s_{hotness}
$$
其中$\beta=0.2$为热度权重。最终返回得分最高的 top-K 个结果。

### 结果内容提取

对于返回的每个检索结果，系统**根据其层级类型**提取内容：**叶子节点**（level=2）通过 client.read(uri) 读取文件全文；**非叶子节点**则拼接其摘要（abstract）与概览（overview）得到**结果内容**，作为recall的计算依据。**结果内容**截断至 2000字符后，作为上下文块传递给后续的 prompt 构建阶段。

## 数据删除阶段

评测完成后，系统执行数据清理以恢复初始状态。OpenViking的清理操作通过client.rm("viking://resources", recursive=True)递归删除所有已入库资源，包括向量索引数据和物理文件存储，随后关闭客户端连接并删除本地存储目录。系统记录清理操作的总耗时，该阶段不涉及 LLM 调用，故token消耗为零。
